Data and Schema

Data & Structure

This system integrates heterogeneous environmental observations into a unified relational database designed to support reproducible scientific analysis.

Rather than storing datasets independently, all observations are structured within a shared schema that enforces spatial, temporal, and relational consistency. This enables direct comparison across data types, monitoring scales, and time.

The following sections explore how the database behaves as an integrated system, highlighting patterns in data sources, temporal growth, structural

📥 Data Sources

The database integrates multiple observational domains, each representing a different aspect of the hydrothermal system:

  • Regulatory data (NDEP) — long-term geochemical records
  • Field measurements — site-specific sampling campaigns
  • Laboratory analyses — high-quality analytical chemistry
  • Temperature loggers — continuous thermal monitoring

Each source differs in temporal resolution, structure, and analytical purpose.

Bringing these datasets into a common framework allows relationships to be established between measurements that were previously isolated.

This integration is essential for interpreting the hydrothermal system as a coupled hydraulic, thermal, and geochemical process.

🔄 Data Flow

All data entering the system pass through a controlled sequence of transformations:

Raw Input → Validation → Standardization → Database → Derived Outputs

Key features of this process:

  • Raw inputs are never modified
  • All transformations are scripted and version-controlled
  • External identifiers (e.g., station codes) are translated into internal database keys
  • Invalid or inconsistent data are rejected during ingest

Archival and Provenance

To preserve reproducibility:

  • All raw field templates are archived before ingestion
  • Templates are cleared only after successful ingest
  • This prevents duplication while maintaining a complete history of inputs

🧱 Database Structure

The system is built on a normalized relational schema with the following core tables:

  • Locations — spatial reference points
  • Sampling_Events — time-based groupings of observations
  • Samples — discrete physical observations
  • Field_Measurements — in-situ measurements
  • Lab_Analyses — analytical chemistry results
  • Temperature_Observations — high-frequency time-series data

Design Principles

  • normalized relational structure
  • strict foreign key relationships
  • append-only time series (no overwriting)
  • explicit separation of raw vs. derived data

🌡️ Continuous vs Discrete Data

A key feature of the system is the integration of:

Discrete observations

  • field measurements
  • laboratory chemistry

Continuous observations

  • temperature logger data

Continuous data enable:

  • detection of short-term variability
  • temporal pattern recognition
  • higher-resolution system monitoring

📈 System Growth Through Time

The database evolves through discrete ingestion events rather than continuous accumulation, reflecting how environmental data are collected and integrated.

Interpretation: Each increase corresponds to a specific ingestion event, such as a field campaign, regulatory update, or logger deployment. Key Insight: The stepwise growth pattern provides explicit provenance, allowing users to trace how and when data entered the system.

⚖️ Data Granularity: Continuous vs Discrete Observations

A defining characteristic of the system is the coexistence of continuous and discrete data.

Interpretation: Continuous temperature observations dominate the total number of records, while discrete datasets (chemistry and field measurements) provide analytical depth. Key Insight: This multi-scale structure enables the system to capture both high-frequency variability and chemically diagnostic signals.

🕒 Temporal Distribution of Observations

Understanding when data are collected is critical for interpreting system dynamics.

Interpretation: Clustering reflects episodic data acquisition, including sensor deployments, field campaigns, and regulatory sampling. Key Insight: Temporal structure reveals not only system behavior, but also sampling strategy and data availability constraints.

🗺️ Spatial Coverage (Sample Points)

Spatial distribution determines how well the system is observed across the hydrothermal field.

Interpretation: Observed clusters represent areas of active monitoring, while gaps indicate potential regions of uncertainty or under-sampling. Key Insight: Spatial structure directly influences the ability to interpret hydrothermal flow paths and system heterogeneity.

📊 System-Level Interpretation

Taken together, these patterns describe a system that is:

  • incrementally constructed through controlled ingestion workflows
  • composed of heterogeneous but integrated data sources
  • dominated by high-frequency continuous observations
  • structured across irregular temporal sampling intervals
  • spatially distributed according to monitoring access and priorities

The database is not simply a collection of datasets—it is a structured representation of system observation itself.

🔬 Geochemical Modeling Integration

Validated chemistry is transformed into PHREEQC-ready inputs, enabling process-based interpretation of hydrothermal conditions.

These transformations support:

  • forward speciation modeling
  • inverse geochemical modeling
  • evaluation of mineral saturation states

This step links observational data to thermodynamic interpretation, extending the system beyond monitoring into predictive modeling.

🔁 Reproducibility and Provenance

All transformations within the system are:

  • scripted
  • version-controlled
  • reproducible

No manual edits are made to database contents.

Every dataset can be:

  • traced to its original input
  • reconstructed from raw data
  • validated through ingestion logs

This ensures that all analyses performed using the system are transparent, auditable, and reproducible.

📸 Image Data

Photographic observations are stored as structured metadata and linked to:

  • locations
  • sampling events
  • field measurements

Images are stored externally, while metadata remain relational.

✅ Current State

The system is actively evolving:

  • continuous temperature monitoring is fully integrated
  • field and sampling workflows are operational
  • laboratory chemistry ingestion is expanding

In operational mode, the database evolves incrementally, providing a live representation of the hydrothermal system through time.
