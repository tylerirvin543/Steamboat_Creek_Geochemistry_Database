About

About This Platform

This site documents a reproducible hydrothermal data system built for the Steamboat Springs geothermal field south of Reno, Nevada, integrating groundwater hydraulics, continuous thermal and conductivity monitoring, and field and regulatory geochemistry into one analytical framework. It is developed by Tyler Irvin, a graduate teaching assistant at the University of Nevada, Reno, working through the Great Basin Center for Geothermal Energy (GBCGE), whose broader mission — geothermal resource assessment, hydrothermal system characterization, and applied geochemistry and hydrology — this project’s data infrastructure is built to serve directly.

The full codebase (every ingestion script, schema definition, and analysis pipeline behind this website) is public at github.com/tylerirvin543/Steamboat_Creek_Geochemistry_Database, and the repository, not this rendered site, is the authoritative source of truth: every table, every derived figure, and every page on this website can be regenerated from raw inputs by running run_pipeline.R.

Design Philosophy

The system is built around one governing idea: data should be structured so that interpretation emerges from the system itself, rather than depending on someone remembering which spreadsheet has the current version of a number. In practice, that means raw inputs and derived products are always kept separate, every transformation is scripted and version-controlled rather than performed by hand, and every ingestion step is idempotent — re-running it on the same files, or on files that have already been partially processed, never duplicates or corrupts what is already in the database. That reproducibility is what lets the system behave less like a static dataset and more like a living framework that keeps its footing as new field seasons, lab batches, and sensor downloads arrive.

Tools Behind the System

The data-engineering layer runs on R (principally the tidyverse, DBI, and RSQLite) writing into a SQLite database; analysis and visualization draw on ggplot2, plotly, and leaflet; spatial outputs are packaged as GeoPackage layers for direct use in ArcGIS and QGIS; and the geochemical modeling this system is building toward runs on PHREEQC. This website itself is generated by the same pipeline, via R Markdown and rmarkdown::render_site(), so it never drifts out of sync with whatever the database currently contains.

Use of Generative AI

Generative AI tools assisted with code structuring, debugging, and the drafting and refinement of this documentation. Every output was reviewed, validated against the actual database and codebase, and adapted to this project’s specific requirements before being kept; all scientific interpretation, data-quality judgment calls, and well-identity determinations throughout this system remain author-reviewed and author-driven.
