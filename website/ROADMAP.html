Steamboat Hydrothermal System – Data Architecture Roadmap

Project Vision

This project builds a fully reproducible, query-driven hydrothermal system platform for Steamboat Springs.

The system integrates:

  • field sampling
  • NDEP regulatory chemistry
  • NDWR hydrologic data (wells + water levels)
  • continuous temperature sensors
  • laboratory analyses
  • isotope datasets (future)
  • geochemical modeling outputs (PHREEQC)

All data are stored in a single relational database and accessed through derived views and analysis workflows.

Core Design Philosophy

Single Source of Truth

All raw data are stored in one SQLite database:

database/geochem_operational.sqlite

This database contains:

  • normalized tables
  • enforced relationships
  • reproducible ingest pipelines

Layered Architecture

The system is structured into three layers:

RAW TABLES - original ingested data - never modified after ingestion

DERIVED VIEWS - computed and cleaned datasets - reusable across analysis and GIS

ANALYSIS AND EXPORT - R scripts perform computation - RMarkdown produces reports - GeoPackage exports deliver GIS-ready layers

Separation of Responsibilities

Database: - stores all raw and derived data

Ingest scripts: - load and standardize external datasets

Views: - define analysis-ready datasets

R scripts: - perform calculations (gradients, mixing, etc.)

RMarkdown: - visualization and interpretation

GeoPackage: - GIS-ready outputs

PHREEQC (future): - geochemical modeling layer

Modular Expansion

New data types are added through:

  • new tables for raw data
  • new views for derived results
  • new scripts for analysis

Hydrologic System (NDWR Wells)

Structure

Wells table defines physical wells
Water_Level_Observations stores time-series measurements
Locations provides spatial reference

Analysis Views (Core Hydro Layer)

vw_hydraulic_head - computes hydraulic head from depth-to-water - includes measurement method flags - primary dataset for flow analysis

vw_water_level_latest - most recent measurement per well - used for mapping water table surface

vw_water_level_daily_best - one measurement per well per day - prioritizes manual measurements over sensors

vw_hydraulic_head_clean - filtered dataset using only high-quality measurements - used for gradient analysis and modeling

vw_wells_gis - GIS-ready well dataset - includes depth classification

Analysis Workflow

Structure

R scripts compute results
RMarkdown produces outputs

Components

Views: - reusable datasets

R scripts: - located in scripts/analysis - perform calculations

RMarkdown: - located in analysis/ - produces figures and reports

Key Rule

RMarkdown should not contain heavy computation.
All computation should occur in views or scripts.
